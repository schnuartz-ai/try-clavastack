# BlueWallet browser adapter

`/blue-wallet/` renders the original BlueWallet 8.0.1 `App.tsx`, providers, navigation and wallet screens from MIT-licensed commit `0a53056a636370073a58d6cdd6de5c0728e5926a`. The submodule stays unchanged. `browser/build-bluewallet.mjs` verifies that pin, applies explicit browser transformations, bundles the original application, and records original/transformed source hashes, adapter and lockfile hashes, bundled input paths and every output hash.

This is an offline Testnet3 simulator. Bitcoin address/WIF/BIP32 versions, BIP44/49/48/84/86 coin types, and SLIP132 versions are adapted to Testnet. Upstream import, derivation, QR codecs, PSBT combination and signing algorithms execute unchanged. Identifiable Mainnet extended keys, addresses, descriptors, and PSBT derivations/global extended keys are rejected. Signing methods also check PSBT metadata. A seed and an unmarked raw transaction/PSBT do not identify a network; use public synthetic fixtures only. No network transport or broadcast is available. Lightning, Ark, notifications, Tor, native security and USB signing are unavailable.

React Native Web renders original screen trees. Adapters cover browser camera/image decoding, context menus, modal alerts, document picker/share operations, local clipboard, and tab-memory Realm/AsyncStorage/keychain boundaries. Explicit flex/width adjustments keep the original scanner and hardware-PSBT screen within the browser viewport. The native receive-QR reveal decoration is omitted on web because its native worklet mask remains opaque; the original QR component and value remain unchanged. Camera access begins only after Use camera; cancellation, route departure and Stop camera stop the stream. Standard SeedQR uses BlueWallet's original parser. CompactSeedQR is a documented browser extension converting a single 16/32-byte QR entropy segment to a mnemonic using the pinned BIP39 package.

`browser/companion-workbench.js`, `browser/companion-media.js` and `browser/companion-file-dialog.js` provide shared SD/card/QR transport. BlueWallet has a separate media store and only the existing public Testnet demo set. First file-dialog initialization waits for the shared media state. Original BlueWallet menus provide file import/export. Menus open on tap when upstream marks them as primary actions, or on right-click/hold when upstream requests a context menu. QR transport forwards the payload rendered by the original QR component with a stable token throughout an animated sequence.

Build with `npm ci`, `npm ci --ignore-scripts --legacy-peer-deps` in the pinned submodule, then `npm run build:bluewallet`. With the isolated test server running, `npm run test:bluewallet` checks original UI import/storage, independent BIP84 derivation and decoded receive QR, 12/24-word SeedQR, synthetic single-signature/multisig signing, Mainnet rejection, camera denial/image fallback, original SD dialogs, and original BlueWallet → Specter QRHost/review/signing → BlueWallet parsing with independent ECDSA verification. Fixtures come from `browser/demo-data.js`; firmware test setup uses its native RAM keystore and never enters the shipped runtime.

CI packages the complete site using `deploy/package-site.sh`, unpacks that actual archive, verifies all BlueWallet asset/license hashes and runs import/signing and desktop/mobile visual tests against the staged `/blue-wallet/` URL. The existing atomic release workflow publishes only after all checks pass. Test helpers are available only on localhost with `?test=1`; production embeds no test seed and exposes no test helper.
